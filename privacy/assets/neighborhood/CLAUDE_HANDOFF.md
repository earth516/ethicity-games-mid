# Claude Code 작업 지시 — 주택가 확장과 철창 교체

## 요청

이 폴더의 새 에셋으로 기존 privacy 게임의 마을을 작은 주택가로 확장하고, 과도하게 높고 촘촘한 철창을 낮은 담장·열린 교문·생울타리로 교체해 주세요. 이번 납품은 에셋과 지시서이며 게임 연결은 아직 하지 않았습니다.

착수 전에 상위 AGENTS.md, privacy/CLAUDE.md, 최신 git diff를 확인하세요. 다른 에이전트가 변경한 테스트와 코드를 되돌리지 마세요. privacy 밖의 게임·공통 저장 규격은 변경하지 말고 push/배포는 하지 마세요.

## 주택가 구성

1. 기존 주인공 집은 유지하고 이웃집 3채를 추가합니다. 집 옆 1채, 길 건너 2채가 엇갈리게 보이는 구성이 목표입니다. 같은 집을 나란히 복사하지 마세요.
2. 현재 맵은 48×23으로 매우 작습니다. 동쪽·남쪽 마을 영역을 확장하세요. 64×34 정도를 검토하되 실제 가구 비율·이동 거리와 화면을 보고 확정하세요. 이는 설계 제안이며 검증된 좌표가 아닙니다.
3. 학교 → 교문 → 연못·벤치 쉼터 → 주택가 → 우리 집 흐름을 유지하세요. 모든 집 앞에 짧은 진입로와 여유 공간을 둡니다. 그림의 현관 위치와 길이 맞아야 합니다. 남쪽 배치 주택도 현관 앞으로 접근하는 옆길이 필요합니다.
4. 새 이웃집은 외관·조사만 제공합니다. 진입 가능한 것처럼 느낌표나 텔레포트를 만들지 마세요. 문을 조사하면 짧은 생활 대사(예: ‘저녁 준비하는 냄새가 난다’)만 보여줍니다. 실제 개인정보는 사용하지 않습니다.
5. 주인공 집 현관 옆 노란 우편함을 두어 구분합니다. 현관과 인접 상호작용 칸을 막지 마세요. 새 집 때문에 본편 목적지가 헷갈리지 않게 합니다.

## 울타리 교체 — 이번 범위에 포함

- 학교 경계는 낮은 아이보리 벽돌 담장과 짧은 세이지색 난간으로 교체합니다. 1.5칸 높이 캐릭터의 허리 정도로, 기존 감옥 같은 높은 세로봉은 제거하세요.
- 가로/세로 방향 에셋을 구분하세요. 가로 그림을 단순 90도 회전하면 광원·원근이 어색해집니다. 끝 기둥을 매 칸 반복하지 말고 긴 구간의 중간 부분과 기둥을 나눠 이어 붙이거나 여러 칸짜리 세그먼트로 사용하세요.
- 코너는 기둥으로 자연스럽게 마감하세요. 이미지가 완벽한 자동 연결 타일이라는 가정은 금지합니다.
- 교문은 양쪽 석재 기둥과 열린 문입니다. 현재 교문은 세로 경계 x=22의 y=16,17을 통해 좌우로 통행합니다. 그림의 열린 공간이 실제 통행 칸에 맞아야 합니다. 문짝은 통로를 가리지 않도록 배치하세요.
- **실제 생성 결과 주의:** gate-parts.png는 완성된 세로 교문이 아니라, 기둥+열린 문짝 부품 두 개가 가로로 나란히 놓인 그림입니다. 전체를 한 번에 늘려 그리지 마세요. 이미지 가운데를 기준으로 좌우 부품의 알파 경계를 각각 구해 source crop하고, 위쪽·아래쪽 기둥으로 재배치하세요. 그 사이 통행 간격을 2칸 확보합니다. fence-side.png도 약간의 원근 기울기가 있어 자동 연결 타일로 간주하면 안 됩니다. 긴 구간과 모서리를 실제 화면에서 검증하세요.
- 마을 가장자리는 낮은 생울타리·관목으로 연결하되 집과 길을 가리지 마세요. 충돌 영역과 시각적 경계가 일치해야 합니다.
- 학교 명패 ‘솔빛학교’는 PNG에 구워 넣지 않고 코드에서 읽기 좋은 텍스트로 표시할 수 있습니다.

## 현재 코드의 좌표 의존성 — 구현 전 재확인

- world.js: W=48,H=23. 마을 외곽 나무는 y=11, y=22, x=47에 고정되어 있습니다. 맵 크기만 늘리면 옛 나무 벽에 막히므로 마을 외곽도 재배치하세요. 학교의 경계는 별도로 유지하세요.
- 주인공 집 외관은 map.js에서 (41,13), 5×5칸으로 그립니다. 문은 world.js DOORS의 (42,18) → (34,7), 방 출구 (34,8) → (42,19)입니다. 가능하면 유지하고 이동해야 한다면 그리기/DOORS/INDOOR.entrance/안내 표시/저장 복원/테스트를 모두 함께 고치세요.
- 내 방은 x=30..39,y=2..8의 별도 숨겨진 실내입니다. 새 집과 섞거나 삭제하지 마세요.
- 연못은 world.js의 (27,19),4×2 물 칸과 map.js의 draw pond (26.9,21.1),4.2×2.2가 연결됩니다. 이동 시 둘을 함께 수정하거나 데이터 기반 배치로 바꾸세요.
- 기존 H/o는 주인공 집 전용 처리와 연결됩니다. 새 집을 같은 문자로만 찍으면 그림·문이 잘못 연결될 수 있습니다. 이웃집별 footprint/render bounds/door interaction을 가진 배치 데이터가 적합합니다.
- 큰 집 그림은 화면 밖 기준점에서도 화면 안으로 들어올 수 있으니 전체 render bounds로 컬링하세요. 나무·사람·문·건물의 앞뒤 순서도 확인하세요.
- 기존 school.js 지붕 표시와 room.js 실내, 팬더 인형 및 학교 내부 미표시 기능을 유지하세요.

## 저장과 성능

기존 진행 저장 위치가 새 건물/울타리 안에 들어갈 수 있습니다. 이어 하기에서 유효한 가까운 통행 칸으로 복구하되 스토리·완료 결과를 초기화하지 마세요. localStorage의 다른 게임·공통 플레이어 값은 보존하세요. 알파 경계 계산/텍스처 캐시 생성은 로드 시 한 번만 하세요. 이미지는 매 프레임 스캔하지 마세요.

- PC·390px 모바일에서 주택 4채의 구분, 현관 진입로, 낮은 담장, 열린 교문, 생울타리를 실제 캡처로 확인.
